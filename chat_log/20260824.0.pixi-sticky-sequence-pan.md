## Problem/Context
Rapid panning remains visibly choppy. The pointer handle initially appeared to die when leaving the canvas, but instrumentation shows pointer routing continues and frame delivery stalls.

Three measured 100-move drags in headless Chromium produced:

```text
run 1: capture 1, moves 100, frames 168, dropped 88, p95 23.9 ms, max 52.1 ms, sticky requests 101, flushes 94
run 2: capture 1, moves 100, frames 67,  dropped 41, p95 24.0 ms, max 25.1 ms, sticky requests 92,  flushes 67
run 3: capture 1, moves 100, frames 49,  dropped 27, p95 24.9 ms, max 25.0 ms, sticky requests 93,  flushes 49
```

This classifies the observed symptom as sustained rendering near 40 FPS rather than lost pointer capture.

The user requested integration with RxJS and the repository signals abstraction. The correct intended boundary already exists in `@hafley66/scene`: `frame$.pipe(pixi()(host)).subscribe()`. The terminal `subscribe()` is empty and owns lifetime; rendering side effects belong inside the `pixi()` renderer operator. A signal source can retain camera state without a side-effect callback in `subscribe`.

## Solution/Approach
1. Keep pointer capture and pan probes.
2. Measure the render path before changing rendering representation.
3. Test Pixi render groups for the imported SVG scene. Render groups may move camera transforms to GPU-side group transforms without rasterizing the scene.
4. Compare render-group enabled/disabled runs using the same 100-move gesture and pan receipt.
5. If traversal remains expensive, add timing around Pixi render execution and separate SVGScene traversal, culling, text, sticky projection, and browser event costs.
6. Integrate the final camera/frame path through signals + RxJS + `@hafley66/scene` operators. Empty terminal subscription only.

## Key Insights
- `pixi-viewport` emits `moved` directly from pointer events.
- The sticky scheduler collapses multiple requests before one ticker callback. A deterministic test proves 80 requests become one flush.
- Real Playwright `mouse.move(..., { steps })` yields across browser frames, so it cannot deterministically prove same-frame coalescing.
- Pointer capture is acquired once and routes moves after the pointer leaves the canvas.
- The pan probe accumulates in memory and writes its receipt once at pointer-up, avoiding per-move DOM writes.
- Pixi text resolution is updated on `zoomed-end`, avoiding per-frame text rerasterization during zoom.
- The app ticker stops after interaction, avoiding idle CPU usage.
- Do not put render or signal-write side effects in a terminal `subscribe` callback.
- All repository-owned lifecycle teardown is named `unsubscribe`. External Pixi methods such as `app.destroy()` remain only at direct third-party call sites.
