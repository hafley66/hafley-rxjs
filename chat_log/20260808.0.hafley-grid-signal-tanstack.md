## Problem/Context
- hafley-rxjs is a pnpm monorepo (`packages/*`), packages use `@hafley66/` scope, vite build via `createLibConfig(__dirname)`, vitest tests colocated `src/**/*.test.ts`, `tsgo --noEmit` typecheck, root tsconfig uses project references.
- The Signal system (packages/signals) has 4 forms: `Signal(state)` BehaviorSubject-cached; `Signal(obs, default)` source form; `Signal(fn)` computed/memo (createComputedSignal, Solid-style dep tracking); `Signal()` bare event (Subject, no replay). `.$` accessor IS a BehaviorSubject. Read `.$()`, write `.$(v)`, `.setImmer`, `.$.$` meta. Nested proxy auto-traverses.
- Doctrine: signals are DECENTRALIZED (no catalog/registry/store; rxjs wires at the seam). Effects are RETURN VALUES (returned signals), not descriptors. Grid NEVER fetches (rows signal passed in). Two layers: createGrid (signal space, outside render) + useGrid (React bridge). schema is THE interface; columns derive from ObjectPathsOf.
- packages/path `ObjectPathsOf<T>` generates deep typed paths (now used by grid columns). `5_Route.ts` exists but rolls its own matcher, lacks hash/JSON/payload — pulse-route plan supersedes it.
- Two repo hooks enforce style: `prose-prod` (no em dashes, banned words, no neg-parallelism, no deictic filler) and `comment-prod` (max 2 consecutive comment lines, constraint-only).

## Solution/Approach
- createGrid<TData extends RowData>(config) returns { schema, state: Signal<GridState>, events: Signal<GridEvent|undefined>, rows: Signal<TData[]> (derived memo: lodash orderBy in client mode, passthrough in server), columns: ColumnDef<GridFeatures,TData>[] (derived from schema), mode, getRowId, onSortingChange, onPaginationChange }.
- gridFeatures = tableFeatures({rowSortingFeature, rowPaginationFeature, paginatedRowModel: createPaginatedRowModel()}). manualSorting: true always (rows signal pre-sorted). manualPagination: true in server mode.
- v9 generics: ColumnDef<GridFeatures, TData> and Table need TFeatures first. RowData = `Record<string,any> | any[]`. useGrid omits return annotation, lets useTable infer.
- config.schema: z.ZodType<TData> infers TData. columns?: Partial<Record<ObjectPathsOf<TData> & string, ColumnSpec>> where ColumnSpec={header?,visible?}. deriveColumns: default=top-level ZodObject keys; else override map keys; accessorKey=deep path.
- onXChange handlers write the state signal slice + emit a GridEvent (so seam is testable in node without React).

## Key Insights
- Signal "Memo" IS an effect + cache: createComputedSignal returns SignalCreator({observable, read: readMemo}). Eager recompute only when observed; pull-only otherwise. Cache is what makes it a memo vs a stream.
- signal/rrxjs isomorphism: combineLatest=Signal(fn) reading many .$(); map=fn body; switchMapCached=createQuery (4_Query.ts:179,196) with built-in per-key cache; reach for rxjs only for .cache invalidation/TTL.
- The fetch circuit is consumer-side: state memo -> createQuery(endpoint, request$) -> rows memo -> createGrid({rows}). Grid is passive terminus. cycle: grid.state -> request -> query -> rows -> grid.
- signalMap should be a PIPE OPERATOR (re-emits on signal change using last source value), NOT a signal-returning helper. Completion is an OPEN FORK: BehaviorSubjects don't complete, so it can't complete with source; consumer owns teardown. withLatestFrom-style variant (completes w/ source, no re-emit) is a different operator.
- Only read surface is .$(); only write surface is .$(value). No other signal access.
- v9 breaking vs v8: useReactTable->useTable, tree-shaken tableFeatures({...}) required, sortingFn->sortFn, column pin left/right->start/end, generics <TFeatures,TData,TValue>.
