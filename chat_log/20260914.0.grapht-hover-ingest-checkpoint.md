## Ingest and Hop Pipeline: Verified Facts
- Sequence fixture generation uses d2SequenceAdapter / mermaidSequenceAdapter, source parsers, buildSequenceArtifact, sequenceDocumentToGraph. Relations, source spans and ordinals are saved to fixture JSON; SVG provides geometry/bindings.
- Runtime proof loads pre-generated paired-d2.json, paired-mermaid.json, and large.json plus SVG and original source text.
- D2 architecture currently uses d2SvgFrame, decoding generated SVG base64 group classes for object IDs and connection endpoints. Original D2 source is retained but is not the relation input for this architecture path.
- Generic svgFrame accepts SVG plus optional graph/bindings. SVG geometry alone supplies no semantic endpoints. Plain SVG has no relational hops. Proof Open SVG accepts .svg plus optional .json sidecar; arbitrary local .d2/.mmd source-file loading is not implemented.
- Sequence proof currently overwrites group parentId using rectangle containment via containerOf. Semantic group ownership remains an unfinished ingestion issue.
- graphNeighborhood traverses Graph edges by fromId/toId with BFS; ownership descent consumes zero hops, an edge consumes one. Default both mode depth=2; focus and first hop both opacity1, second .55, unreached .15.
- sequenceNeighborhood instead traverses ordered message event transitions from sequenceFlowOf, including modeled branches. It paints actor endpoints after traversal.
- Both renderers consume the same logical id -> hop map from a Signal in proof/live.ts. Hops are computed by Grapht, not by Cytoscape.
- Native hover coalesces/deduplicates input by animation frame and diffs paint/signatures; palette normalization is cached.
