## Problem/Context
- The library was untestable *by eye*: a board with no page is a model nobody can check, which is exactly how two
  real defects survived unit tests (see Insights).
- The docs sites had no e2e: every `serve` slot built a throwaway fixture app, so nothing asserted the pages that
  actually ship, and there was no proven way to mount repository source into the docs DOM.
- `grapht`'s barrel is not browser-safe (bench harness + `1_sequence/3_geometry.ts` → playwright → native `fsevents`),
  which silently poisons the Vite dep optimizer for a whole dev server if a page imports it.

## Solution/Approach
- **Board identity = the address.** An item's `itemId` **is** its address's `locatorHash`, so a placement is keyed to
  prose rather than a list position. `reconcileBoard` carries a placement onto the relocated item and reports orphans
  instead of moving them. Frames arrive from the host (`withFence`): grapht parses neither mermaid nor d2.
- **No new renderer contract.** `boardFrame(board, { size, viewport })` produces a plain `GraphFrame`; camera from
  `fitGraphCamera`; `geometry.revisionId` a `documentFingerprint` of the placed geometry (viewport excluded); unplaced
  items stack in board order so an un-gestured board paints identically every run.
- **Artefacts beside their document, verified on read.** `<doc>.board.json` and `<doc>.messages.jsonl`, written through
  a pid-named temp + rename (`src/lib/2_artifactFile.ts`), readable only when they validate.
- **Git is the only database.** `Grapht-Artifacts:` / `Grapht-Messages:` trailers + the message's `baseRevision` are
  joined by `grapht-doc-history` (exit codes 2 / 1 / 0 like `grapht-history`); no second index.
- **Docs-site testing via the dev server's module graph.** `/@fs/<abs>` with the site base prefix reaches any workspace
  source; readiness is pointed at the *page under test*; probes import the module, not the barrel.

## Key Insights
- **Two defects only running it could find.** (1) `validateBoard` called "item without a placement" an anomaly, so
  `readBoardFile` refused *every* board a person would actually save — a young board is not a broken one. (2) The board
  page persisted *every* placement on an insert, freezing the stack position of untouched items and calling that a
  decision ("13 placed" when one card had been dragged).
- **Two timestamp traps in `grapht-doc-history`, both caught by running the real bin.** Git writes an author date with
  the author's offset (`-04:00`) while a message may be stamped `Z` — not comparable as strings; and git stamps to the
  second while a message carries milliseconds, so a message written 300 ms before its own commit looked *resolved before
  it was written*. Compare as instants, floored to the second.
- **`git log --pretty=format:` puts a newline between commits**, so every record after the first carried a leading `\n`
  into the revision id. (The older `1_gitWalk.ts` dodged this by filtering blank lines.)
- **Import the module, not the barrel, from a page.** grapht's barrel drags playwright into the browser graph; the
  optimizer then dies on native `fsevents` (invalid UTF-8) and *every* dep chunk 504s until `site/.vitepress/cache` is
  deleted. Same trap the grapht site lane hit; the probe and `BoardDemo.vue` both import `4_board/0_board.js` directly.
- **Readiness must be the page under test.** vitepress dev re-optimizes deps after start; `ready()` retries on ≥400, so
  pointing it at the page waits that window out. A leftover dev server on the port is worse: `ready()` can be satisfied
  by the stranger while `site:content` deletes `site/pages` underneath it.
- **vitest rewrites a literal `import()` in a test file** into `__vite_ssr_dynamic_import__`; the page has no such
  helper — use `new Function("u", "return import(u)")`.
- **Every docs page 404s the hub strip** (`/hafley-rxjs/strip.js`, Pages root only), so the site suites set
  `log: { failOnConsoleError: false }` and replace it with a narrowed guard (no failing request except the strip; no
  console error that is not a 404). JS exceptions still fail.
- **`matchPage` proves shape, not identity**: `:page` matches any single segment, so only content assertions catch a
  slug the site does not serve (measured by deliberately asserting a wrong slug).
- **`locatorHash` needs an in-place edit to stay put** — it derives from `${section}/${ordinal}`, so an *inserted* block
  above shifts it; relocation falls through to `contentHash` (unique → reanchored, 0 or 2 → orphaned). An
  insertion-stable structural id is phase 6's and would change every persisted address.
- **`git commit -- <path>` cannot add new files** (needs `git add` first), and two `git` commands in one tool block race.
