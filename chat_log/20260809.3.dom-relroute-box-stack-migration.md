## Solution/Approach
- Relative routing: literal skeleton of template (`/grid/:gridId/row/:rowId`
  -> `grid/row`) matched against composed `data-route` segments; params filled
  from ancestor `data-*` (dataset camelCase: `data-row-id` -> `rowId`). One
  element stamps its segment, descendants inherit params -> no prop currying,
  less DOM verbosity than absolute `id`-stamping.
- `boxAttrs` is framework-agnostic (testable in jsdom); `Box` is the thin react
  layer. Separation keeps rxjs-ext core dep-free.
- Stack migration: a single JSON-aware node script applied versionMap + removed
  rolldown/native-preview refs across root + 9 packages; then resolved the
  cascading compat issues (dts plugin, TS7 compiler API, config imports) one by
  one. Verify per package with `tsc --noEmit` + `vitest run` / `node --test`.

## Key Insights
- `mergeByKey`/`mergeByKeyScan` (`rxjs-ext/src/3_mergeBy.ts:15,81`) are the fold
  primitive. `Signal(observable)` is dual (obs merged with imperative `.$()`
  writes, `1_SignalCreator.ts:72-81`, refCount). Never naked `.subscribe`.
- `Dom(template)` already exists (`8_domTemplate.ts:82`); treats DOM events as a
  routed API. Absolute mode (`Dom(t).$.click`, full-`id` regex walk) + now
  relative mode (`Dom(t).route.click`, data-route segments + inherited params).
- Signal proxy paths (`path.join("/")`, `1_SignalCreator.ts:154`) align with
  route literal skeletons -> one addressing system. String index keys work
  generically; numeric/dynamic keys leak via the lazy `??=` cache (`:277`).
- TS 7 dropped the JS Compiler API -> `@typescript/typescript6` is the required
  fallback for any dts-generation tooling.
- path package tests are `node:test` `.mjs`, not vitest; run via `node --test`.
