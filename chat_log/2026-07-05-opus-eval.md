## 1. @hafley/signals

### Architecture read

Single root `BehaviorSubject`; every node is a lazy lens over it (lodash-path get,
immer set with structural sharing). Dual interface at every node: `.$()` pull with
tracking via `signalDispatch` "get" events, `.$.pipe` push with explicit temporal
composition. Both modes are views of the same root subject, so there is no
dual-source-of-truth reconciliation problem. `Base`/`$field` + `createBase(root,
path)` is the plugin seam (FormSignal-class extensions per node).
`signalDispatch`'s event union (create/subscribe/get/set/unsubscribe) is the
introspection bus the debugger consumes.

### D design: collection nodes (agreed direction)

1. When a node's value is array/Record/Map (`IsRecursive` in `0_types.ts` already
   distinguishes this, so the type layer has the hook), the node runs ONE
   subscription that pairwise-diffs consecutive emissions into `{added, removed,
   changed}` key sets. Skip entirely when ref-equal (immer). Key-child nodes
   subscribe to `diff$.pipe(filter(d => d.touched.has(k)), map(get))` instead of
   independently selecting from root. Cost per root write: one O(changed) diff
   instead of N x (get + compare).
2. Iteration surface on the same stream: `state.users.$each()` emitting keyed
   diffs; rxjsx children reconciliation is the natural consumer; the devtool gets
   `{type:"diff"}` meta events for free.
3. Eviction: refCounted shareReplay handles the subscription half already; node
   objects for dynamic keys get `WeakRef` + `FinalizationRegistry` (or LRU);
   `??=`-forever stays for static struct fields where it is correct.
4. Explicit form (`state.users.k(id)`) preferred over implicit detection: less
   magic, clean type split between struct traversal and dynamic keying.
5. This is `signal_map`/`signal_vec` (futures-signals `MapDiff`/`VecDiff`), solid's
   `mapArray`, jotai's `splitAtom`: the JS and Rust designs converge on one model.

## 2. @hafley/rxjs-ext

Closest to shippable; README undersells it. `renext` + `makeSwitchMapCached` +
`mergeByKeyScan` composed is TanStack Query as three orthogonal operators:
staleness triggers, keyed request cache with TTL (`share` + `ReplaySubject(1)` +
`resetOnRefCountZero: timer(ttl)` is the right rx-native cache shape), and
loading/data/error accumulation. The composed worked example belongs in the README;
it is the pitch. `combinePartialRecord`/`mergeByKeyScan` are the state-from-events
primitive that `combineLatest` refuses to be, and rxjsx already consumes them,
validating the layering (ext is the base; signals and rxjsx are both clients).

Notes: `switchMapCached` never forwards inner `complete` (outer completes only with
source; deliberate for caches, diverges from `switchMap`, document it). Default
`keyFn = JSON.stringify` is key-order sensitive (one doc line).

## 3. @hafley/rxjsx

Solid without the compiler: JSX to `Observable<VNode>`, purity computed at runtime
on the observable graph (`IS_PURE` + `.pure()` hoisting is the analog of Solid's
static template cloning). Core `merge(attrs$, children$) -> scan` is
combinePartialRecord restated; attrs already use ext.

Strain: the snabbdom boundary (`jsx-runtime.tsx:103-119`, style deleted twice,
attrs/props/data juggling). The graph knows which attribute changed and then
discards that by rebuilding the whole `h()` node and re-diffing. Endgame: bind each
observable prop directly to a DOM mutation (Solid's runtime); keep keyed
reconciliation only for dynamic children. The manually-unrolled `Prims` type
(`:203-234`) collapses under the `DepthLimit` recursion trick already in signals
`0_types.ts:8`.

## 4. Smash / kneeman: the routed-signal model (echoed and agreed)

Inventory: three reducers of one shape plus a cell bag.

| Layer | Reducer | Write path | Read path |
|---|---|---|---|
| frame sim | `step(state, input, tune)` | input funnel (rollback owns it) | `state_cell: Mutable<SimState>` echoed per frame |
| durable world | `fold(build, log)` | `WorldRuntime::append` (single funnel) | `world()` re-fold |
| menu nav | `Nav::reduce` | Intent vec drained after egui frame | `Location` |
| ui cells | none | direct `Mutable::set` in kneeman | `Mutable::get` |

The model in pseudo-rxjs:

```ts
const frame$   = input$.pipe(scan(step, spawn()))     // 60hz, rollback-owned
const world$   = event$.pipe(scan(fold, genesis))     // durable log
const session$ = new BehaviorSubject<Session>(local)  // which engine is mounted

const S = Signal(session$.pipe(switchMap(s => s.frame$)))  // THE singleton

S.fighters[0].pos.$()   // read: last echoed frame, always sync
S.tune.gravity.$(0.2)   // write: routed command
//  local session: dispatch(Set(path, v)) -> reducer -> frame$ -> echoes into S
//  net session:   rides the funnel; S updates on the CONFIRMED frame
const UI = Signal({ route, charsel, toasts, gizmos })  // locally authoritative
```

One sentence: a signal node is a selector and an action-creator fused, and which
store backs it is a switchMap upstream of the root. Writers never learn whether
their set was a local next or a command that echoes two frames later.

Hazards recorded: (1) path-writes never enter the ggrs input vocabulary
(fixed-size; peers desync); the routing layer enforces per-subtree policy.
(2) Echo write is async under netplay; sync read-after-write lies for a few
frames; surface as pending/confirmed meta (same shape as `BgSource::Missing`).

Event-names ruling: pathed batched writes ARE the action vocabulary for the 1-1
class (`Act::Set(PathId, Value)` / `Act::Txn`, one generic reducer arm). Formal
names survive in exactly three places: durable logs that outlive the schema
(PathId enums renumber on struct edits; `world/migrate.rs` exists for a reason),
multi-path intents where per-path LWW is the wrong merge under sync (`Reset{to}`),
and rollback inputs. Frame sim and ui state are never replayed across schema
versions, so path-writes cover them entirely.

Rust kit plan: `~/projects/games/smash/plans/rust-signals-kit.md`. Nine sessions:

## 5. rxjs-debugger (devtool-plugin): the priority project

Owner intent recorded this session: UI half deprioritized. The project's real
question was always "how much of the react-hmr playbook transfers to rx", and the
answer is structured by the ways rx differs. Goal: runtime + transform + HMR
identity rock solid first; kit translation for kneeman second.

### What exists (read this session)

1. **Build-time rxjs patch** (`1_runtime_vite_plugin/0_rxjs_devtool_patch_plugin.ts`):
   regex-patches the Observable constructor in the rxjs dist across three build
   formats (ES5 IIFE / ESM class / TS source) to inject `__oid__` creation + a
   constructor-call-return event, plus `decorateOperatorFun` wrapping of operator
   files and optional creation-fn decoration. Warns when a pattern misses.
2. **AST user transform** (`2_user_transform.ts`, oxc-parser + magic-string): wraps
   observable declarations as `__$("data$:hash", factory)` and subscriptions as
   `__$.sub(...)`, with `_rxjs_debugger_module_start(import.meta.url)` scoping.
   Declaration-site keys give observables stable identity across module
   re-execution.
3. **HMR runtime** (`0_runtime_hmr/`): `__$` resolves existing track by key,
   produces `trackedObservable`/`trackedSubject` stable wrappers so external
   subscribers survive an inner-source swap. BehaviorSubject current values are
   preserved into the new wrapper. Subscription-context prefixing
   (`$ref[obs]:subscription[id]:location`) names dynamically-created inner
   observables.
4. **Tracker core** (`0_runtime/0_store.ts`): `event$ -> scanEager` fold into typed
   stacks + stores (observable, operator_fun, operator, pipe, subscription, arg,
   arg_call, send, hmr_track, hmr_module, fun, call, arg2). Built on a self-hosted
   diet-rx (`lib/2_diet_rxjs.ts`) so the debugger never observes itself.
   `shouldEmit` gates on enabled + hmr_track stack, with an UNTRACKED_EVENTS
   allowlist. `suppressSend$` suppresses internal subscriptions during wrapper
   plumbing.

Architecture verdict: the layering is right and is the strongest design in the
monorepo. Event-sourced debugger state means the debugger inherits replayability.
The stable-identity-via-source-transform choice (vs runtime WeakRef guessing) is
the correct one and is the novel contribution: nothing else in the rx ecosystem
does HMR-stable observable identity.

### react-refresh <-> rx concept mapping (the props/op-params/ctors question)

This is the section to internalize; every HMR task below derives from one of these
rows.

| react-refresh concept | rx analog | the difference that matters |
|---|---|---|
| component identity (name + file) | declaration site key (`varName:hash`) | already matches; rx also has anonymous inline pipes that react does not (every `.pipe()` in an argument position) |
| signature (hooks order + custom-hook deps) decides preserve vs remount | pipe-chain signature: creator + operator sequence + operator arg SOURCE TEXT | does not exist yet; today swap-vs-preserve is keyed on declaration site only, so editing an operator lambda preserves a wrapper whose behavior changed |
| props: re-supplied by the parent on every render, flow through automatically after swap | upstream emissions: re-flow only on resubscribe, and only if the source is hot or replayed | after a swap the new inner pipe sees NOTHING until the upstream emits again; react gets a free re-render, rx does not. This is the biggest divergence |
| hook state (useState/useRef survive refresh) | subject state: BehaviorSubject value, ReplaySubject buffer, scan accumulators, shareReplay buffers | BS value already carried over. Scan accumulators and shareReplay buffers live inside operator closures and are unreachable by construction: they can only be rebuilt by replay |
| remount (signature changed): state reset | resubscribe: teardown + re-run side effects of cold sources | resubscribing a cold source re-fires effects (fetches, timers). Needs an explicit policy, not an accident |
| error boundary retry | rx error channel is first-class | swap-on-error can resubscribe a completed/errored graph: a capability react does not have; make it a feature |
| families (forwardRef/memo wrappers resolve to same family) | wrapper chains: trackedObservable(trackedSubject(x)), `.pipe()` of tracked | `isTrackedWrapper` early-return exists; family resolution across pipe boundaries does not |

Constructor/params difference, stated once: react props are late-bound (arrive per
render), rx operator params are early-bound (closures captured at pipe time, over
module state that HMR just replaced). So rx HMR has to treat operator args as part
of identity (signature) AND as potentially swappable units (fine-grained arg swap),
where react never needs either.

### Task list

Grouped; rough order inside each group. (Priority ordering across groups at the end.)

**T1. Tracker core correctness**
- T1.1 `shouldEmit` matrix test: every event type x enabled on/off x hmr_track
  stack empty/nonempty. The UNTRACKED_EVENTS allowlist and the stack gate are
  where silent event loss will hide.
- T1.2 Stack discipline property test: for any tracked program run, every
  `*-call` has a matching `*-call-return`, stacks end empty, and store entries
  reference only ids that exist. Generate small random pipe programs and assert.
  This one test hardens the entire fold.
- T1.3 Event grammar spec: write the `ObservableEvent` union down as a doc with
  per-event invariants (who emits, required context, ordering guarantees). The
  accumulator switch in `0_store.ts` is the implementation; the spec is what makes
  refactors safe.
- T1.4 `events$` accumulator: `scanEager((a, b) => a.concat(b))` is unbounded and
  O(n^2) over a session. Replace with ring buffer + retention config, or an
  indexed store with sequence numbers (the store half already exists; events$ may
  only need to hold a window).
- T1.5 Id determinism: `_idCounter` gives session-relative ids. Derive observable
  ids from (track key, instance seq) so two runs of the same code produce
  comparable traces; keeps cross-session diffing and persisted-trace replay on the
  table. Remove the `_idCounter === 35` debug stub (`0_store.ts:45`).
- T1.6 Self-observation rail: the diet-rx boundary is an import-graph invariant
  (`0_runtime/**` must not import rxjs except type-only). Write it as a sprefa
  `.dl` rail so `dl --check` fails the commit that leaks. Same rail for the
  `noRxjs()` marker convention.
- T1.7 `suppressSend$` audit: enumerate every internal-subscription site that
  should suppress and test each; a missed suppress double-counts sends, a stuck
  suppress drops user events.
- T1.8 store_v2 decision (`0_store_v2.ts` exists, 280 lines): merge or delete;
  two accumulators is one too many.

**T2. User transform hardening**
- T2.1 Formalize `rxjs-edge-cases/` into snapshot fixtures: in/out pairs, run in
  CI. Cases to cover beyond the obvious: destructured declarations, class
  properties, `export default pipe(...)`, observables returned from functions,
  conditional creation, observables created in loops (dynamic keys: the loop
  index must enter the key or all iterations collide), pipe chains split across
  variables, namespace imports (`rx.of`), re-exported observables, `satisfies`/
  `as const` wrappers, JSX-embedded observables (rxjsx interop).
- T2.2 Idempotency: transforming already-transformed output must be a no-op (HMR
  re-transform path). One fixture asserts this for every case in T2.1.
- T2.3 Self-exclusion: the debugger's own packages and diet-rx must never be
  transformed; test the include/exclude regexes against the monorepo layout.
- T2.4 Sourcemap e2e: magic-string map composed through vite; assert a thrown
  error inside a wrapped factory points at the original line (one playwright or
  vitest-browser check).
- T2.5 Key hashing spec: what exactly is hashed into `varName:hash` today; write
  it down, then extend to the signature hash (T3.1) so the two stay one concept.

**T3. HMR semantics (the react-refresh port, adjusted for early-bound params)**
- T3.1 Signature hash per declaration: creator name + operator sequence + operator
  arg source text (oxc already has the spans). Swap decision becomes: same key +
  same signature -> preserve wrapper and inner (no-op); same key + changed
  signature -> swap inner, apply state policy. This is react-refresh's
  signature, transplanted.
- T3.2 State policy per swap, explicit and per-source-kind:
  BehaviorSubject: carry value (exists). ReplaySubject: carry buffer.
  Subject: nothing to carry. Cold creator: resubscribe (side effects re-fire:
  document loudly). scan/shareReplay internal state: rebuildable only via replay
  (T3.3) or reset; NEVER silently pretend it carried.
- T3.3 Replay-based rebuild (the differentiator): the tracker already records
  send events per observable. On swap of a derived pipe whose sources are tracked
  subjects, re-feed the recorded upstream emissions through the new pipe with a
  virtual clock to rebuild scan/shareReplay state, then splice live. Scope
  gate: only offer it when every source is a tracked subject with full recorded
  history; refuse otherwise. This is redux-devtools reducer-hot-reload
  generalized to arbitrary pipe graphs, and nobody has it for rx.
- T3.4 Fine-grained arg swap: when the signature diff localizes to ONE operator's
  lambda (e.g. only a `map` fn body changed), swap that closure in place (wrap
  operator args in identity-stable cells at transform time: the arg/arg_call
  stacks exist for this) instead of tearing the wrapper's inner. React-refresh
  cannot do this; early-bound params make it possible here.
- T3.5 The re-emission gap: after any swap, the new inner emits nothing until
  upstream fires. Policy options per node: replay-last (BS-like sources), poke
  (renext-style trigger on swap), or wait. Make it visible in the meta events
  either way so "why is my stream silent after save" is answerable.
- T3.6 Cross-module graph: dependency-ordered re-execution when module A exports
  an observable consumed by module B (`4_module-scope.ts` is the seam). Define
  vite HMR boundary acceptance: A changes -> A re-executes, B's wrappers keyed on
  A's exports re-resolve without B re-executing. Test with a 3-module diamond.
- T3.7 Teardown ordering on swap: old inner unsubscribed before/after new inner
  subscribes (choose and test both glitch semantics; default: subscribe-new-first
  for BS-backed, teardown-first for effectful cold sources).
- T3.8 Completed/errored graph revival on swap: define whether a wrapper whose
  inner completed re-opens after HMR. (Suggest: yes, with a meta event; this is a
  debugging superpower, label it.)

**T4. rxjs patch plugin robustness**
- T4.1 Version matrix CI: patch + boot a smoke app against rxjs 7.4 through
  latest 7.8.x (and 8 alpha if tracked), asserting the pattern matched and one
  constructor event fired. The three regexes are pinned to dist shapes; this is
  the most likely total breakage.
- T4.2 AST fallback: same patch expressed via oxc on the dist file when regexes
  miss, so an rxjs patch release degrades to a slower path instead of a warning.
- T4.3 Fail-fast option: config to turn the "Pattern did not match" warning into
  a build error (default on in CI).
- T4.4 Snapshot the patched output per rxjs version in fixtures, so a bump shows
  the diff in review.
- T4.5 Document why both the constructor injection and the runtime
  `patchObservable(Observable)` exist (creation-site capture vs prototype
  behavior), so future-you does not delete one.

**T5. Leak detection (the package.json headline)**
- T5.1 Define the leak taxonomy as queries over the store: subscription alive
  after its module was HMR-disposed; refCounted share never reaching zero;
  subscription with no teardown reachable from a disposed root; subject with
  subscribers but no upstream. Each is a select over state$, which is the payoff
  of event-sourcing the tracker.
- T5.2 `WeakRef`/`FinalizationRegistry` sweep: `obs_ref.deref()` exists in the
  store; add a registry pass that emits a `leak-suspect` event when a tracked
  observable is collected while its subscription record is still open, and the
  inverse (subscription closed, observable uncollected after N GCs) as a
  retention suspect.
- T5.3 One command surface: `debugger.leaks()` returning the query results as
  data (UI optional, per this session's deprioritization).

**T6. Perf + data model**
- T6.1 Operator-level timing: `decorateOperatorFun` already brackets calls;
  record per-operator wall time into the store so a flamegraph is a query later
  (data model now, UI never-mind).
- T6.2 Sampling/budget mode: cap event rate per observable id (drop + count) so
  a hot mousemove pipe cannot swamp the fold.
- T6.3 Serialize/restore a session: events are already the state; add
  export/import of the event log (ties into T1.5 stable ids).

**T7. Parked (UI)** marble diagram, debugger grid, app.tsx: no tasks this pass,
per owner call. The data-model tasks above (T5.3, T6.1, T6.3) keep every future
UI a pure consumer.
