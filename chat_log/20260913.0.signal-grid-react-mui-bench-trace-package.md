## Key Insights

- **`reactSlot` was rendering nothing.** `createRoot` is concurrent, commits cell bodies off the
  animation frame, and a grid under load never yields one. Chaos counted **0 filled cells of 416**
  while reporting a higher frame rate than the DOM writer. `flushSync` + a `{host, root}` pool fixed
  it: opt-in cost went 2.00x the DOM slot to 1.39x, and now beats MUI X on script.
- **MUI X MIT caps a page at 100 rows.** `<DataGrid />` forces `pagination: true` and `pageSize`
  throws above 100, so its scroller is 3,600 px deep whatever `rows` carries. The head to head is
  per frame or it is nothing.
- **Where MUI X wins:** layout 6.8x and style 4.7x cheaper per frame. At the only depth both
  support it spends 2.57 ms of measured work against our 3.15.
- **Where we win:** script 1.4x to 2.9x, first row 1.5x to 3.7x, heap 1.3x to 2.6x, p50 1.78x at
  2560x1440, and 990x the scroll depth.
- **Fifteen of sixteen chaos drivers are free.** Only `colWidth` written every frame breaks the
  frame (38 fps, 101 slow of 193) and it has the *lowest* package cost of the expensive ones.
  Writing a grid track is one browser layout of every rendered row.
  `DEFAULT_DRAG_MODE = "preview"` (`src/7_epics.ts:83`) means a real resize never does this.
- **LogTape found 3 of 5 chaos defects and actively misled on the other 2.** It sees the package's
  own stages only. `colWidth` read 1.28 ms/f, the lowest. Empty React cells cost nothing inside the
  package because React had not run yet.
- **`longtask` attribution is useless** on a one-page app: `name: "unknown"`, `containerType:
  "window"`. It only names iframes. LoAF (`long-animation-frame`) names the *file* and splits
  script from style-and-layout, which is the half LogTape cannot see.
- **`window.open` copies sessionStorage.** Measured in chromium. That copy is the parent link: a
  document with an opener, or below `window.top`, holds an id that is not its own.
- **A worker has no sessionStorage and no localStorage.** `self.name` is the only channel reaching
  it before its first message, hence `workerName(parentPid, service)`.
- **`performance.timeOrigin` is the process start**, verified equal to
  `Date.now() - uptime * 1000` and 14 ms before the module that asked for it loaded.
- **A pid is not a key.** `pid@born` is.
- My own driver defects, each one a consumer would write too: pinning the row under the scroll
  forced a full base replan (29.7 ms/f), a triangle over the whole scroller measured a cold mount
  60 times a second, and firing 4 DOM events every frame was 240 a second (11.4 ms/f).

## Open Questions

Mid-discussion on the trace life/death model, **no code written yet**, deliberately:

1. **Who reports a death.** Node can self-report (`process.on("exit")`, lossy on SIGKILL). A tab
   cannot (`beforeunload` is not guaranteed). So `died: number` or
   `died: number, certainty: "reported" | "timeout"`.
2. **Is an orphan a new edge or an ended one.** Unix reparents a child to pid 1 when its parent
   dies. A gantt of edges wants `vitest->vite` to end and `vitest->pnpm` to begin. A tree render
   wants one edge with `until` set, because it still has to draw something.
3. **Does an edge belong to the child or to neither.** Child-owned needs the child alive to report a
   reparent, which fails when the child is what died. Its own row needs a third party, which means
   a collector.

Proposed shape, not built:

```
Key   = `${pid}@${born}`
Span  = { key, ident, born, died? }
Edge  = { child: Key, parent: Key, since, until?,
          cause: "spawn" | "open" | "attach" | "reparent" | "orphan" }
```

Asymmetry the type must admit: an ancestor always outlives the node; a browser descendant cannot
outlive its host (terminating a worker kills its sub-workers) but a node one can (orphan).
