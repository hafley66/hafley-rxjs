## Problem/Context
- THREE copies of the same `compile(template)` regex + `fill()` lived in xdom,
  signals Route, and the canonical `@hafley/path`. Consolidation, not invention.
- `@hafley/path` `ValuesOf<Template>` parses `:name` colon syntax at the TYPE
  level too (`0_types.ts:41`), so xdom's colon templates typecheck against it.
- `PathPart` is an exported discriminated union (`0_types.ts:80`):
  literal/property/optionalProperty/restProperty. skeleton = literal parts joined.
- `path.concatenate(other)` already composes parent+child templates — the
  ".2 deferred builder" was never new; it's `concatenate`.
- `print` THROWS on a missing required param (`Missing path value: id`), stricter
  than the old silent `"undefined"` fill. Test updated to assert the throw.
- Generic-cast issue: `ValuesOf<Path>` not comparable to `Record<Params<Path>,
  string>` over an unresolved generic `Path` → cast through `unknown`.
- User corrections this session (important to remember):
  - "Proxy JSX members" was embellishment — don't invent; use existing packages.
  - Per-field encode/decode is the worst layer — global devalue (one param, JSON
    blob). `devalue` for the codec.
  - Persist is a `tap`, not `.subscribe`.
  - Stop doing side effects: encapsulate the observable graph in signals; React
    projects via `use$`; or don't do it.
  - Storage read/write must be observable ("a pancake in time") — source + sink.
  - Storage lives in signals; path stays rxjs-free (zero rxjs deps, usable
    outside any reactive context).

## Solution/Approach
- Path consolidation: `slash(template)` returns the typed `IPath`; `print`/`match`
  replace `fill`/`compile`; literal `parts` replace `skeletonOf`. Both xdom and
  signals Route drop their local copies and gain `@hafley66/path: workspace:*`.
- Memo guard: one-line `if (!event)` wrap; safe because no existing memo test
  depends on event-signals-as-deps (verified, not assumed).
- Storage trait: the backend is a duplex observable channel
  (`read: Observable<T>`, `write: Observer<T>`). localStorage/URL/chrome.storage
  are 2-line adapters impl'ing it. `storageSignal` binds any backend, devalue via
  `{serialize, parse}`. Synchronous seed captured via an eager first-read sub.

## Key Insights
- `defineConfig(fn)` returns the fn unchanged — `config.x = ...` after
  `createLibConfig(dir)` is a no-op; call the inner fn first to override.
- One unbuilt dist cascades phantom type errors far afield (build before
  debugging types).
- `boxAttrs` stamps the FULL template skeleton on each Box; nested same-template
  Boxes compose to a doubled skeleton and DON'T match. Single-Box-per-endpoint
  (full stamp) works; multi-node inheritance = `path.concatenate`.
- Absolute mode (`dom.$.click` + `dom.id(values)`) and relative mode
  (`dom.route.click` + `<Box>`) coexist; absolute is verified in the 6/6.
- `signalHistory` (`signals/src/9_history.ts`) is the history→signal wrapper
  (location/action as signals, swappable browser↔memory). `8_sync.ts` `sync()`
  is the loop-guarded pure signal↔signal bind (NOT for impure backends).
- Storage as observable duplex: a backend is `{read: Observable<T>, write:
  Observer<T>}`. Same trait for localStorage/URL/chrome.storage. devalue is the
  typed-value↔string codec.
- Path is deliberately rxjs-free (the "core outside rxjs"); signals owns
  observable state, storage, routing.
