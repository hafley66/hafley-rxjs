## Solution/Approach
**The IR.** `columns: number[]` — the virtual milliseconds at each causal column — and
`lanes: [{ id, label, parent, born, notifications }]` where a notification is
`{ id: string; kind; tick; value?; note?; from? }`. Frames belong to the column, not the event: two
events in one column are at the same moment by construction. Six kinds: `next | error | complete |
subscribe | unsubscribe | truncate`. Lane ids are `[A-Za-z][A-Za-z0-9_-]*` so an event id
(`lane#n`, 1-based production order) is splittable. `marbleEdges(doc)` states the edges; `marbleAxis(doc)`
is the D9 geometry (`pitch = clamp(PITCH, gap/unitMs × PITCH, MAX_PITCH)`, break past the cap).

**Two producers.** `marbleDoc(input)` takes `{ tick | after, ms, frame, kind, value, note, from }` per
event, builds the document-wide column clock from a forward cursor, and validates everything (unknown
kind, misspelled field, backwards tick, duplicate lane id, unknown `parent`/`from`, contradictory pin,
non-monotonic clock). `runMarbleDemo` drains the `TestScheduler` one action per column
(`drainVirtual`, the only code touching `actions`/`execute`/`frame`) and records the higher-order family
by wrapping the observable a project returns and handing the wrapper to the *real* operator:
`lanes.through` (one shared subscription) and `lanes.each(id, source, project, { op, name, seed,
innerLabel })` which builds `mergeMap`/`switchMap`/`concatMap`/`exhaustMap`/`expand`/`mergeScan`/`switchScan`
and records one named inner lane per subscription with its birth column, causing event, seed, and fate.

**The reveal.** `player.revealed: Signal<number | "all">`; `step(±1)` is one column, `play` walks and
restarts at 0 from the end, `revealAll` restores the picture. Nothing seeks.

**The surface.** Axis with per-column ms labels and break marks, a legend, `title` on every marble,
notes under their marbles, SVG edges (dashed = birth, solid = value routing, hidden until both ends
have happened), a column readout in words, hidden = `display: none`.

**Proved by measurement.** `describe("geometry")` in the chromium suite: marble within 1px of its own
column's label, one column one x, per-column marble count equals the document's, lane containment,
pitch floor/cap, break placement, readout restricted to one turn.

## Key Insights
- **A tick cannot be reconstructed from frames.** `of(1,2,3)` is one turn and three turns rescheduled
  share every frame; only the producer knows. So `tick` is document data or it does not exist.
- **`observeOn(asapScheduler)` over a synchronous burst is ONE turn, not three.** The plan's original
  measurement was wrong: `observeOn` buffers while the source delivers synchronously and drains the
  buffer in a single action. The honest one-turn-per-value demo is
  `of(1,2,3).pipe(concatMap(v => of(v).pipe(observeOn(asapScheduler))))` — four columns, all at 0ms.
- **`TestScheduler.run` flushes with no frame limit the moment its callback returns.** A live `interval`
  left on the queue is an infinite loop, not a diagram — the first symptom was a hanging suite. The cut
  and the teardown have to happen *inside* the callback, before `drainVirtual` returns.
- **An absolutely positioned child measures from the padding box**, so `padding-left` on the axis moved
  no labels. It needs a margin (and the axis needs an explicit width, or it disagrees by the gutter).
- **`box-sizing: content-box` put 11px of gut between the strips and the axis**: `.mb-gutter` was
  `flex: 0 0 168px` plus padding and a border, so its box was 179px while the axis assumed 168.
- **A glyph is not a sentence.** `^`/`⌄` are legible only to their author: the surface needs a legend
  and a per-marble description.
- **Reading the rendered picture is a verification method.** Every number in the renderer was
  self-consistent while the labels sat a gutter from their columns; only measuring the DOM found it.
- **The higher-order family needs names and edges, and nothing else.** Wrapping the project's result in
  an Observable is enough to record birth/cause/seed/fate for all eight operators without
  reimplementing one — `switchMap` cancelling an inner is an `unsubscribe` with a note on that inner's lane.
- **A window is not a cancellation**: `truncate` for the harness closing keeps the three operator fates
  unambiguous.
- **The subscription law still holds**: the package has zero `.subscribe(` outside `5_render.ts`, and
  the demo's one boundary is `runWhenInView`, which subscribes and drops it with the host's visibility.

## Open Questions
1. **What is the layout abstraction?** Today: one geometry table (`marbleAxis`) that every consumer
   positions from numerically — single-source, but hand arithmetic. The proposed next step is CSS grid
   tracks (one track list per column, shared by all lanes and the axis row), which makes alignment
   structural. Do we also want the strips to become one grid with lane rows, or keep per-lane grids?
2. **Where does the perf readout live?** `docs-kit` is `private: true` (unpublished), so only demos can
   use it. Move the readout to `@hafley66/trace` (published, already owns `metrics$`), or publish
   `docs-kit`? The user says the code is public, so the licence is not the blocker — the npm manifest is.
3. Does the published surface *want* a perf HUD at all, or is demo-only the right answer?
4. `exhaustMap` starting no lane for a value that arrived while an inner ran is visible only as an
   absence; there is no event for a value nothing handled. Worth an annotation?
5. `expand` over a synchronous seed is one column because recursion is not a queue boundary; the parent
   chain, not the axis, is what makes that readable. Is that enough?
