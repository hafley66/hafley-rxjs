## Solution/Approach
- **Lanes, then integration by the primary.** Three workers (xdom act, MdAddress, markdownGraph), disjoint paths,
  no commits; every receipt re-verified by running the lane's own command before committing per-lane.
- **Docs-site testing**: VitePress's dev server *is* Vite, so a page can `import('/<base>/@fs/<abs path>')` any
  workspace source, cross-package, transformed on demand — proven by HTTP (200 `text/javascript` for
  `packages/signals/src/index.ts` served by signal-grid's dev server) and then in the live page (200 exports mounted
  into `.VPDoc`). `serve: { kind: "command" }` already existed; no runner change was needed.
- **Routes by `@hafley66/path`**: `docs-kit` exports `PAGE_SEGMENT = slash(":page")`; each site composes
  `slash(BASE).concatenate(PAGE_SEGMENT)` into `SITE_PATH`, with `pageUrl(page, query?)` and `matchPage(pathname)`.
  `@hafley66/signals`' `Route(template, { base })` is the browser-side form (it reads `location` at construction, so
  it cannot be built in the node test process).
- **Board identity**: an item's id **is** its address's `locatorHash`, so placements key to prose, not to list
  positions; `reconcileBoard` carries a placement onto the relocated item and reports orphans instead of moving them.
  Frames arrive from the host (`withFence`), because grapht parses neither mermaid nor d2.

## Key Insights
- **The dev server is the docs DOM's module graph.** `/@fs/<abs>` with the site base prefix reaches any workspace
  source; no `fs.allow` needed (Vite finds the pnpm workspace root). Preview serves built assets, so mounting is
  dev-only. The dev server binds the *name* `localhost`, not `127.0.0.1`.
- **Readiness must be the page under test**, not the site root: vitepress dev re-optimizes deps after start and a
  document request inside that window 504s; `ready()` retries on ≥400, so pointing at the page waits it out.
- **vitest rewrites a literal `import()` inside a test file** into `__vite_ssr_dynamic_import__`; the page has no such
  helper. Use `new Function("u", "return import(u)")` for in-page loading.
- **Every docs page 404s `/hafley-rxjs/strip.js`** (hub strip, Pages root only). Both suites set
  `log: { failOnConsoleError: false }` and replace it with a narrowed guard (no failing request except the strip; no
  console error that is not a 404). JS exceptions still fail via `failOnPageError`.
- **A leftover dev server poisons the suite**: `ready()` can be satisfied by a foreign server while `site:content`
  deletes `site/pages` underneath it — the 504/reload cascade is the tell. Check `lsof -nP -iTCP:<port> -sTCP:LISTEN`.
- **`matchPage` proves shape, not identity**: `:page` matches any single segment, so only content assertions catch a
  slug the site does not serve (measured by deliberately asserting a wrong slug).
- **Two timestamp traps, both measured by running the real bin** (`grapht-doc-history`): git writes an author
  date with the author's offset (`-04:00`) while a message may be stamped `Z`, so they are not comparable as
  strings; and git stamps to the second while a message carries milliseconds, so a message written 300ms before
  its own commit looks resolved before it was written. Compare as instants, floored to the second.
- **`locatorHash` needs an in-place edit to stay put**: it derives from `${section}/${ordinal}`, so an *inserted*
  block above shifts it. Relocation absorbs it (unique content hash → reanchored; 0 or 2 → orphaned). A structural id
  that survives insertion is phase 6's, and it would change every persisted address.
- **grapht's barrel is not browser-safe**: it drags the bench harness and `1_sequence/3_geometry.ts` (which imports
  playwright) into a page, crashing the optimizer on `fsevents`. Import the module, not the barrel, from probes.
- Two pre-existing generator defects, untouched: signal-grid's committed `docs/reference-api.md` is missing
  `SG_DRAG`; signals' regenerates into `re-export … : any` bodies because `0_log.ts` re-exports from `@hafley66/trace`.
