## Solution/Approach
- Test environments per package: node for pure code, Chromium (vitest browser mode) for DOM code, `@hafley66/vitest-playwright` for the whole page. e2e needs explicit `timeouts: { action, navigation }` — playwright defaults to none and a bad selector otherwise burns the 120s test budget instead of failing in 10s.
- md's `fixtures/` mounts the panel over an in-memory host; the serve slot builds and previews it, so the e2e suite drives the real page.
- Worker dispatch (user turn, this session): bounded-context subagents for the next tasks while the primary coordinates and reviews. Herder doctrine applies (`skill://herder`): one written end per job, disjoint owned paths, compact receipt, verify before integrating, scoped commits by the primary.
- Lane split for the next wave (files disjoint, no shared mutable file):
  - Lane X: xdom React `act` warnings — zero `act(...)` console errors in the xdom browser suite, suite still green, no behavior change unless the warning reveals a real defect.
  - Lane H1: phase 2 — `MdAddress` + `locatorHash`/`contentHash`/`docHash` + one WebCrypto hash twin, in `packages/grapht-model` only.
  - Lane H2: phase 3 — `markdownGraph(document): Graph`, in `packages/grapht` only, consuming existing `grapht-model` exports.
- Frozen contract so H1 and H2 can run concurrently: block ids stay `${section}/${ordinal}`; `locatorHash = sha256Hex(`${path}#${blockId}`)`; `contentHash = sha256Hex(text.slice(span.start, span.end))`; `docHash = sha256Hex(text)`. H2 depends only on block ids, H1 only on adding hashes, so no regeneration of `grapht-model/dist` is needed mid-flight; H1 builds at the end.
- boop is installed (`boop beep lane create --branch/--brief`, worktree-per-lane). Chose harness `task` subagents for this wave because they share this kernel and filesystem, so the primary can verify the diff directly; boop lanes remain the path for volume on external harnesses.

## Key Insights
- A test that cannot fail is worse than no test: jsdom turned 13 skipped xdom tests and 3 fake scroll tests into green signal that measured nothing.
- `.subscribe()` / lifecycle teardown naming: new teardown in this repo is `unsubscribe`, never `dispose`/`destroy` (pre-existing `dispose` in virtualizations stays at the call site).
- The fence origin travels in the fence **metastring** — the only field Streamdown gives a fenced renderer besides code/language/incompleteness — because overriding `pre`/`code` to read `node.position` strips the container, language label, copy button, and Shiki tokens.
- `documentFingerprint` is a 32-bit FNV and stays an in-memory revision id; persisted addresses use sha256, so the board needs one WebCrypto twin (adapters already do this privately, e.g. `packages/grapht/adapters/2_render_cytoscape/src/3_fixture.ts:36`).
- In the md panel today no bound SVG element is in the DOM (Cytoscape canvas + overlays), so the element-id → span join only completes once the pin layer renders a sealed SVG or a DOM renderer.

## Open Questions
- Does the WebCrypto hash twin live in `grapht-model` (leaf, importable by browser lanes) or in `grapht` (which already has `node:crypto`); the plan says the board needs the twin, not which package owns it.
