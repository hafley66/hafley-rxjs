## Problem/Context
- Grid↔URL binding resolved = **option A**: location read-only derived Signal; route is the typed interface; raw location is wire format; URL changes via `history.push(to)` side-channel. route already gives both directions (`href` encode / `match` decode).
- "Turtles all the way down": any row with children is a container; an open container gains trailing `/`, so a file expanding into markdown AST reads as a folder.
- Two bugs fixed during GridTree dev: (1) toggle `onClick` wrapper (`stopPropagation` + `()` no-event) didn't drive expansion → mirror GridTable's `onClick={row.getToggleExpandedHandler()}`; (2) 1px screenshot dimension flake from non-integer text line-heights → `lineHeight:1` + DOM row-count guards before screenshots.
- CRITICAL signal warning stands: never proxy-index a signal array (`rows[0].$()`) — numeric proxy keys lazy-instantiate and leak.
- **instant comparison** (`~/projects/instant`, Tauri+React19): files tab = FilesPanel→FileExplorer→FileTree over canonical `TreeTable` (react-table **v8** + react-virtual), already does markdown-AST turtles + lazy Tauri `list_dir`. instant pins react-table ^8, grid pins ^9 (coexist nested). Verdict: don't swap engine; extract shared kernel into grid.
- **MUI X tree-data** studied + rejected: flat rows + `getTreeDataPath` + `rowExpansionModel`; eager path model, lazy-awkward, buggy. Rejected wholesale.
- Lazy seam design: grid = event source + rows sink + renderer, NO loader inside. Two-wire cycle: `expand$` → rxjs `loadChildren` → `rows.$`. `visibleRows` = refCount computed Signal; `expand$` = hot Subject.

## Solution/Approach
- GridTree: flat `getRowModel().rows` from react-table; column-id conventions (`__expand`, `name` indent); trailing slash keyed on `row.getIsExpanded()`.
- createLazyTree: flat rows + `parentId` + expanded `Set` signal; `visibleRows` DFS groups children under parent regardless of flat-array append order; loading derived (expanded && no loaded children); `expand(id)` flips set + emits `onExpand.$(id)`; `expand$` exposed as `Observable<string>` via `onExpand.$ as unknown as Observable<string>`.
- The consumer cycle: `tree.expand$.pipe(mergeMap(async id => ({id, kids: await loadChildren(id)}))).subscribe(({kids}) => tree.rows.$([...rows, ...kids]))`.
- React-binding principle: every subscription rides a component lifecycle (useSignal/useObservable effect+teardown) OR is shared (`share`/`shareReplay`). Naked bootstrap `.subscribe()` is the anti-pattern.

## Key Insights
- `Signal(fn)` memo (`createComputedSignal`) is the refCount bridge; `visibleRows` shares `rows`+`expanded` reads across all readers.
- A bare `Signal<T>()` is a hot Subject (no replay) — ideal for `expand$` events; multiple subscribers share one source.
- DFS-by-parentId makes the consumer's append-anywhere work; children group under parent regardless of flat-array order.
- Loading is derived, never stored: `expanded.has(id) && !rows.some(r => r.parentId === id)`.
- `lineHeight:1` fixes sub-pixel screenshot dimension flakes; DOM row-count guards before screenshots prevent capturing transient frames.
- react-table does NOT virtualize — `@tanstack/react-virtual` `useVirtualizer` does (separate hook, fed by the row model).
- MUI X = flat rows + path + ancestor-expanded filter; eager. Grid's lazy `children()` resolver is lazy-native.
- instant's `store.subscribe(cb,[keys])` bootstrap cluster (`main.ts:221-451`) is the anti-pattern the signal seam replaces.
