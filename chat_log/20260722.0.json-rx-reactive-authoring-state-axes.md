## Problem/Context
The authoring target is reactive semantics independent of a host Rx library. A portable JSON-RX graph must preserve typed payloads, event cause, current-value availability, state history, concurrency/cancellation, sharing, and cross-target fixture behavior.

A candidate signal-like surface was discussed using `$`-suffixed bindings and a `$ { ... }` block that would infer current-value reads from `name$` to bare `name`, then lower a static dependency set to `combineLatest(...).pipe(map(...))`. This syntax is deferred. Its unresolved requirements include capture/shadowing, initial values, error/completion, equality, sharing, cancellation/flattening, and provenance.

## Solution/Approach
Maintain separate semantic graph shapes rather than forcing one authoring form to represent all reactive work:

```text
current-value derivation
  latest input values -> projection -> derived value

keyed event fan-in
  named input emission -> { key, value }

partial current-value record
  named flows -> record of Option latest values

state reduction
  prior accumulator + { key, value } -> next accumulator
```

### Keyed event fan-in
Existing `mergeByKey` converts a named record of streams to a tagged event union:

```ts
mergeByKey({ checkout: checkout$, rateLimits: rateLimits$ })
// Flow<{ key: "checkout"; value: Checkout } | { key: "rateLimits"; value: RateLimits }>
```

It preserves the causal source identity for routing and reducers.

### Linear latest record
Existing `mergeByKeyScan(inputs, seed)` is the pointwise record-reduction shape:

```ts
(state, event) => ({ ...state, [event.key]: event.value })
```

The session identified an Option-lifted specialization named conceptually `latestByKey`:

```tsp
latestByKey({ checkout$, rateLimits$ })
// Flow<{
//   checkout: Option<Checkout>,
//   rateLimits: Option<RateLimits>,
// }>
```

It starts all slots at `None`; an observed source value becomes `Some(value)`. This preserves the difference between no prior emission and an actual `null` or `undefined` payload. A complete projection can require every slot to be `Some`, yielding `combineLatest`-style first-emission behavior.

### General state reduction
`scan` is the semantic form for prior-state and cross-field logic:

```ts
reduce(previous: State, event: TaggedEvent): State
```

A reducer transaction receives one tagged event, reads prior state, applies ordered draft-style writes, and commits one next-state emission. TypeScript may lower with Immer `produce`; Rust uses an owned mutable transition value. Reducer blocks do not implicitly capture or subscribe to flows.

This distinguishes a linear latest-slot update from transitions that coordinate fields, indexes, counters, optimistic mutations, validation state, and invariants.

## Key Insights
- Reactive current-value derivation, keyed event fan-in, and previous-state reduction have different temporal contracts.
- `mergeByKey` retains event cause; a signal-style current-value expression does not inherently retain cause.
- `mergeByKeyScan` is a linear same-key slot update. It can serve as a latest-record layer.
- `latestByKey` has Option slots, preserving no-emission independently from `null` and `undefined` source payloads.
- General `scan` owns a state transition and supports cross-field logic in one atomic output transition.
- Portable reactive semantics must be fixture-defined, including emissions, initial values, completion/error, cancellation, sharing, and provenance. Generated target code is not the compatibility record.
