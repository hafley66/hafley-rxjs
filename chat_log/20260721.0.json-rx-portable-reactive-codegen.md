# Session: json-rx-portable-reactive-codegen

## Goal
Author RxJS-shaped reactive programs in TypeSpec, lower them into a parseable portable representation, and generate equivalent idiomatic programs across languages. The first targets are TypeScript with `@hafley66/signals` and RxJS, and Rust with Tokio, futures streams, `futures-signals`, and the existing `@hafley/alloy-rs` TypeSpec-to-Rust generator. Later layers generate typed browser-extension, WebSocket, Axum, service-worker, Tauri, and egui integrations without binding the core to Instant.

## Problem/Context
The broad plan accumulated overlapping abstractions: `JsonRxGraph`, `ReactivePlan`, `BehaviorGraph`, interactions, coroutine state, and deployment planning. The user's actual objective is narrower: write recognizable RxJS once and move it to another language quickly. Pipeline operators are rarely reused and should not be global catalog nodes.

TypeSpec is the primary authoring surface because it provides checked JSON-shaped declarations, references, generics, editor tooling, and polyglot emission. JSON Schema is generated for JSON editor support, runtime validation, and interchange. A second general JSON Schema assignability engine is outside the plan.

Async/query state should be a denormalized reducer record, not a disjoint status union. Retained data, error, loading, completion, stale state, and unsubscribe reason may coexist.

## Solution/Approach
Use three narrow representations:

```text
SchemaGraph
  checked TypeSpec payload model and emitted-schema identities

RxProgram
  named boundaries plus inline RxJS-shaped pipelines

DeploymentPlan
  derived host placement and transport bridges
```

`BehaviorGraph` is only a dependency graph derived from `RxProgram` for type flow, effects, placement, and generation. It is not the authored document shape.

Core shape:

```ts
type RxProgram = {
  schemas: SchemaGraph
  sources: Record<string, SourceDefinition>
  states: Record<string, StateDefinition>
  effects: Record<string, EffectDefinition>
  pipelines: Record<string, PipelineDefinition>
  outputs: Record<string, OutputDefinition>
}

type PipelineDefinition = {
  input: InputExpression
  pipe: OperatorExpression[]
}
```

Operators preserve RxJS terminology: `map`, `filter`, `scan`, `switchMap`, `concatMap`, `exhaustMap`, `mergeMap`, `share`, and `shareReplay`. Their diagnostic identities derive from owner and position, such as `pipelines/pageState/pipe/1`.

Reducer state:

```ts
type ReactiveState<Next, Failure> = {
  status: 'idle' | 'loading' | 'next' | 'error' | 'complete' | 'finalize'
  data?: Next
  error?: Failure
  complete: boolean
  loading: boolean
  stale: boolean
  updatedAt?: number
  unsubscribed?: string
}
```

Rust generation uses `hafley66/hafley-tsp`, package `@hafley/alloy-rs`. It already provides TypeSpec extraction, Rust structs/enums, serde tagging, traits/functions/impls, imports, crate/module emission, Axum endpoint components, multi-transport bindings, code zones, Vitest snapshots, and generated Cargo checks. Extend its union and literal support instead of introducing Typify.

Rust runtime choice:
- Tokio for tasks, timers, and channels.
- futures streams where every event matters.
- `futures-signals` for latest-current-value UI state.

Initial protocol defaults:
- TypeSpec checking is authoritative.
- Generated TypeScript discriminated unions and Rust serde-tagged enums expose typed frames.
- First terminal activation result wins; later completion/failure/cancellation is discarded.
- Missing extension capability fails immediately with typed `capabilityUnavailable`; retry/wait is authored in the Rx pipeline.
- Exact protocol version and catalog hash are required initially.
- Polling is ordinary authored reactive structure and its subscription owns the timer.

Small proof slices:

1. Replace `SnapshotPatchPipeline` with generic inline `PipelineIr` while preserving behavior.
2. Add `map -> filter -> scan` with a closed typed expression AST and shared `[4, 10, 18]` output.

4. Generate denormalized lifecycle reducers in both languages and compare every intermediate state.
5. Bind reduced state to `@hafley66/signals` and Rust `futures_signals::Mutable`.
6. Generate one typed request across a TypeScript/Rust WebSocket seam and Axum handler.
7. Benchmark generated code against handwritten same-language controls.

Performance:
- TypeScript timing through Vitest 4 benchmark fixtures.
- Isolated Node `--expose-gc` fixtures for retained heap and RSS.
- Rust timing and allocation count/bytes through Divan and `AllocProfiler`.
- Focused release-mode peak/retained heap through DHAT.
- Compare generated TypeScript to handwritten TypeScript, and generated Rust to handwritten Rust.
- Workloads include construction, 1K/10K/100K map-filter-scan events, switch cancellation churn, 1/10/100 observer fanout, payload sizes, subscription churn, wire codecs, and Axum fanout.

## Key Insights
- The authored form is an ordered RxJS-like program. The graph is derived.
- Most pipe operators are singleton syntax and should remain inline.
- The current cross-language scan example is already the first proof and should be generalized rather than replaced.
- TypeSpec supplies the type checker. JSON Schema supplies serialized validation and editor interoperability.
- All observable lifecycle state can be reduced into one denormalized record.
- Stream and signal semantics remain distinct in Rust: streams preserve events; signals preserve latest value.
- The user's existing `@hafley/alloy-rs` already covers much of the Rust and Axum generation surface.
- Cross-language correctness uses one canonical event timeline and frame corpus, not separately written expectations.
- Performance tuning begins after semantic equivalence and compares generated code with handwritten same-language controls.
- Browser-extension, Axum, Tauri, and egui examples consume the proven core instead of defining it.

## Open Questions

- Whether `ReactiveState.status` needs both `complete` and `finalize` after terminal teardown, given the separate booleans and unsubscribe reason.
- Exact union/literal gaps in current `@hafley/alloy-rs` extraction.

- Which allocation and throughput regression budgets are stable on the owner's machine after three baseline runs.
