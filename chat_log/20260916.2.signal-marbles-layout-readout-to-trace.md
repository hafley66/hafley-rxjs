## Problem/Context
1. **Layout was numeric.** `xAt(tick) = PAD + columns[tick].x`, marbles `position:absolute; left: xAt(...)`,

   twice — and this exact class had already produced two shipped bugs (an abspos-vs-padding-box axis
   drift of eleven pixels, and a content-box gutter 11px wider than the axis assumed).
2. **Three, not two, marble renderers already exist** (the read the user asked for):
   `packages/devtool-plugin/src/2_ui/1_MarbleDiagram.tsx` (`@hafley66/rxjs-debugger`) is the semantic
   twin — lanes per subscription in the tree, rail = subscription lifespan coloured by state,
   `●`/`|`/`✗` marbles, `⊗` unsubscribe kept distinct from complete, `$` dynamic observable with a title
   naming its origin, legend, time axis, `x = %` of a captured range.
   `packages/marbler/src/0a_TimeViewport.ts:10-13` defines the mark IR (`dot{variant: next|complete|error|suppressed,
   lane, label}` · `span` · `link{from{time,lane}→to{time,lane}}`) and
   `packages/marbler/src/1b_TimeNavigatorPixi.tsx` renders it (lanes, `●`/`|`/`✕`/`○`, bezier links
   between lanes, DOM value labels, density histogram, pan/zoom/brush/fit);
   `packages/marbler/src/2a_DemoViz.tsx:74-84` already ships marble diagrams of `of(1,2,3)`,
   `merge`, `switchMap`, `concat`, `debounceTime` ("suppressed"), `retry`.

## Solution/Approach
**The layout abstraction is a track list.** `marbleTracks(axis, { pad })` (`0_types.ts`) returns the
column tracks — `[pad, ...columns.slice(1).map(c => c.pitch), trailing + pad]` where `trailing = width − last.x`
— which sum to the old `width + 2·PAD`, so nothing reflowed. The renderer writes them once as
`--mb-tracks` on `.mb-scroll`; `.mb-strip` and `.mb-axis` are CSS grids over that one list, so column
`tick` is grid line `tick + 2` for the axis *and* for every lane. A marble is a grid item on that line
(`grid-column: tick+2 / span 1`, `justify-self: start`, `width: max-content`) and `translateX(-50%)`
centres its own box on the line; the only number left in the surface is the per-column stack offset
(`position: relative; top: k·13px`). The axis's leading box now shares one rule with the lane gutters
(`.mb-gutter, .mb-axis-gutter { box-sizing: border-box; flex: 0 0 var(--mb-gutter) }`), which kills the
drift class outright. `xAt`, the inline strip width, `marginLeft`, `minWidth` and the now-dead
`positionIn` walker are deleted.

**The unit is stated once.** Axis labels are bare numbers (`0`, `305`) and the legend carries
`axis: t = turn, number = ms`; the column readout still says `302ms` exactly. The test that pinned the
old strings now asserts the labels equal `player.doc().columns` — the numbers against the document.

**Edge anchors are drawn glyph centres.** `positionOf(entry, origin)` reads
`glyph.getBoundingClientRect()` (`blockquote`-style query `.mb-dot, .mb-bar, .mb-caret, .mb-cut`), takes
its centre, and subtracts the `.mb-lanes` rect — the same origin the absolutely positioned SVG overlay
uses. `origin` is read once per `measure()`; `layout()` now just calls `measure()`.

**The readout moved to trace, realm-optional.** `packages/trace/src/11_performanceReadout.ts` owns it
beside the metrics it prints. `metricsRealm(source = globalThis as RealmLike)` → `{ frames, heap }`
(frames = both rAF functions are functions, heap = `heapEstimate(performance)` is defined);
`frameGaps()` returns `EMPTY` when `frames` is false; `metrics$` uses `realm.performance?.now() ?? Date.now()`;
`memorySample()` reports `undefined` for a heap it cannot read. The readout's note says which reading is
unavailable and why, and rows start at `"sampling"` in a realm that can measure rather than claiming
`"unavailable"`. `RealmLike` is read through a typed `globalThis` alias so `vi.stubGlobal` is still seen,
and the rAF lookup happens at subscribe time so the existing fake-rAF test keeps working.
`MemorySample`/`Metrics` replace a `ReturnType<typeof memorySample>` in the emission type.

**Vitest orphan: measured, not explained.** The pool worker registers no `disconnect` handler
(`grep -r disconnect vitest/dist` matches only `chunks/inspector.CvyFGlXm.js`), so its exit depends on
the event loop emptying when the IPC channel closes. Four runs: SIGKILL and SIGTERM to the main both
took the fork with it; a probe test holding `setInterval` plus a never-settling `await` also lost its
fork within 6s. Survival could not be reproduced, and the pid was killed before it could be autopsied.

## Key Insights
- **A marble cannot be off its column when the column is a grid track**, and the axis cannot drift from
  the lanes when both read one `--mb-tracks` string — measured, not asserted: strips' computed
  `grid-template-columns` equal the axis's, and their prefix sums equal `marbleAxis`'s `x + AXIS_PAD`.
- **Centre, not corner.** An absolutely positioned marble with `translate(-50%,-50%)` made
  `offsetLeft/offsetTop` the anchor by accident; as a grid item the same numbers became the box corner,
  which is how a note's height moved an edge's start. Read the drawn glyph's rect and subtract the
  container's — the container origin is the thing the overlay is positioned from, so it is the only
  correct frame.
- **The gutter is in the coordinates once.** `positionIn(node, container)` returns container-relative
  values; anything that adds `GUTTER` afterwards is a gutter wrong. The `hoverAt` call site had it right
  (`pointer x` is strip-relative, `entry.x` is lanes-relative); `drawEdges` did not.
- **A label's unit is not free.** `305ms` against a 26px compressed column is a 4px overlap; the unit
  belongs in the legend, once.
- **Consumers resolve the built `dist`.** Re-pointing a consumer at `@hafley66/trace` only typechecks
  after `pnpm run build` in trace — the first attempt failed with "no exported member
  `performanceReadout`" for exactly that reason.
- **`docs-kit` re-exports do not make a package published.** The blocker for a public surface was
  `private: true`, so the readout had to move to the package that already owned `metrics$`.
- **Realm-optional is a contract, not a try/catch.** `metricsRealm()` lets a surface decide *before*
  mounting, and the streams complete empty instead of throwing, so importing trace in node is a no-op.
- **Vitest fork workers only exit when their loop empties.** No `disconnect` handler exists in v4, so an
  idle worker dies with its main (measured four ways) and the trigger for the 43-minute survivor is
  unresolved.
- **`vitest run` picked up the browser suite** until the package's own `vite.config.ts` `test.include`
  was checked; trace's `exclude: src/**/*.browser.test.ts` is what keeps mode separation honest.
- **Running a chromium suite without `scripts/browser-queue.mjs` was a mistake this session** (one run);
  the queue is machine-wide and every lane shares the box.
