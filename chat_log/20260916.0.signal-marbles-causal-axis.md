# Session: signal-marbles-causal-axis

## Goal
Build the marble-diagram widget: a document (lanes x ticks) that two producers emit (hand-authored input and real RxJS on a virtual clock) and one signal-driven surface plays back. Then, after review, redesign that surface around a causal axis instead of a timeline. The redesign is planned, not built.

## Problem/Context
User review of the shipped package produced three complaints and two directives, all of which invalidate the current surface:

1. "i need tick (micro task/queue boundaries. inner stream unsub vs complete vs error)". Measured against the current runner:
   - `of(1,2,3)` and `of(1,2,3).pipe(observeOn(asapScheduler))` record IDENTICALLY (subscribe@0, next@0:1, next@0:2, next@0:3, complete@0). One synchronous burst and three scheduler turns are indistinguishable.
   - `from(Promise.resolve(9))` records subscribe@0 + unsubscribe@10000 and **silently loses the value**: `TestScheduler.run` cannot virtualize a microtask, so the emission lands after `flush()` returns and after the package closed its observers. A silent wrong answer.
   - The `switchMap` demo lane records 13,16,19,23 and the inner subscription that `switchMap` cancelled — the entire point — leaves no mark, because the runner only records the terminals of lanes and an inner subscription is not a lane.
2. "hihtting play again at end is replay" — `play()` at the last frame is a no-op today.
3. "idk why its scrubbing a thing over time. i mean sure but how is that helpful to me?" — the axis is wrong. `x ∝ ms` is a timeline (that is `@hafley66/marbler`'s job); a marble diagram is `x ∝ causal turn` with time as an annotation. Everything downstream of that mistake (a playhead that walks wall clock, a scrub that answers no question) follows.
4. "since ai cant count, relying on it to line up ascii or strings vertically is bad, should be sep input to say what tick something is on and as next events timing, instead of relying on any form of marble syntax from rxjs test utils" — the positional notation is a counting task and must not be the primary authoring surface.
5. "a player would hide the not active ones and show them progressively. then we annotate a marble event so we can say why something would happen" — no scrubber; a progressive reveal, plus per-event annotations.

## Solution/Approach
The plan is `plans/2026-09-16-signal-marbles-causal-axis.md`; the axis drawing decision sheet is `plans/2026-09-16-axis-options.md`. Summary:

**Two numbers per notification.** `tick` = the causal column (one turn of the scheduler, or one column an author wrote). `frame` = virtual milliseconds at that turn. Two ticks share a frame whenever anything ran synchronously or on a microtask; that equality is the information. A tick cannot be derived from frames (proved by the `of`/`asap` measurement), so it is document data. `MARBLES_VERSION` goes to `marbles/2`.

**Authoring is structured and needs no alignment.**
```ts
marbleDoc({ title, lanes: [{ id, label, parent, msPerTick, events: [
  { tick: 1, value: "k" }, { after: 2, value: "k" }, { after: 1, ms: 300, value: "idle" },
  { kind: "complete" }, { kind: "unsubscribe", note: "switchMap drops inner #1" },
]}]})
```
Fields: `tick` absolute column, `after` columns after the previous event (default 1), `ms` the time this event costs as a gap, `frame` absolute ms for imports, `kind` (`next`|`error`|`complete`|`subscribe`|`unsubscribe`|`truncate`), `value`, `note`. Zod validates the input. The ASCII notation parser stays but is defocused (README leads with `marbleDoc`, demo authors with `marbleDoc`, `<details>` shows the document).

**Real ticks in the runner (prototyped and measured).** `TestScheduler.run()` drains its queue with no seam, but the drain loop is 12 lines and every field it touches is public (`scheduler.actions`, `action.execute(state, delay)`, `scheduler.frame`, `scheduler.hotObservables[].setup()`). So: inside `run()`'s callback, subscribe the lanes, then drain one action per tick with a copy of that loop; `run()`'s own `flush()` then finds an empty queue. Prototype output (probe deleted):
```
of(1,2,3)                                 tick 0        frame 0     next 1,2,3, complete
of(1,2,3).pipe(observeOn(asapScheduler))  ticks 1,2,3   frame 0     next 1,2,3, complete
interval(1000).pipe(take(3))              ticks 1,2,3   frames 1000,2000,3000
```
Contained in one function `drainVirtual(scheduler, { maxFrames, onTick })` with one pinning test, because the four fields are marked for removal in rxjs v8.

**An inner subscription is a lane.** A registrar form of the runner, because inner lanes are discovered during the run:
```ts
runMarbleDemo(lanes => {
  const outer = interval(12).pipe(take(3))
  lanes("outer", outer, { label: "interval(12)" })
  lanes.each(outer, () => interval(4).pipe(take(3)), { name: "inner", parent: "outer" })
})
```
`each` registers `inner#1..n` as each subscription begins and records its fate: cancelled → `unsubscribe`, finished → `complete`, threw → `error`, each with a note. The object form stays as sugar.

**`truncate` is a sixth kind** — the diagram stopped watching. A harness window is never `unsubscribe`, so the three operator fates stay unambiguous.

**Diagnostics channel.** `runMarbleDemo` returns `{ doc, diagnostics }`, `readMarbleDemo` throws them (mirrors `parseMarbles`/`readMarbles`). First diagnostic: a lane that never emitted and was still subscribed — a Promise or real timer is not on the virtual clock. Second: a lane past a notification cap is told to narrow the window rather than becoming a 10,000-column document.

**The axis (decided: "both, ticks shown but time correct up to a threshold").** One geometry, no mode toggle:
```
unitMs     = the smallest positive gap between consecutive columns in the document
pitch(gap) = clamp(PITCH, (gap / unitMs) * PITCH, MAX_PITCH)      PITCH = 26px, MAX_PITCH = 6 * PITCH
x(0) = PAD ;  x(t+1) = x(t) + pitch(frame(t+1) - frame(t))
break(t)   = the gap exceeded MAX_PITCH: draw a break mark carrying the real milliseconds
```
Every column prints its own ms underneath, so compression is marked rather than hidden.

**The playhead is a reveal, not a scrubber (decided).** `player.revealed: Signal<number | "all">` replaces `position`/`frame`. Three states per marble: hidden / shown / current. Pointer scrubbing is deleted; clicking a lane still selects. Controls: `◀ ▶` one column, `play` walking the reveal, `all` for the finished picture, and `play` at the end restarts at 0.

**Events carry `note`** — the "why" — authored by hand and written by the runner for the fates it observes. Rendered under the marble, revealed with it, emphasized on the current column.

## Key Insights
- A tick cannot be reconstructed from frames. `of(1,2,3)` and `observeOn(asapScheduler)` are identical in frames and ordering; only the producer knows. So `tick` is document data or it does not exist.
- `run()` sets `maxFrames = Infinity` and calls `flush()` itself, which is why `scheduler.maxFrames` cannot bound a run — the current code bounds it with `takeUntil(timer(frames))` per lane. The redesign replaces that with owning the drain loop.
- Ticks can be counted without any cast because `AsyncScheduler.actions`, `AsyncAction.execute`, `VirtualTimeScheduler.frame`, and `HotObservable.setup` are all public (the first three are "deprecated, internal in v8" — hence one containing function plus one pinning test).
- The subscription law: a library never calls `.subscribe()`. This package's one exception is `5_render.ts`, documented as a boundary because a renderer owns native nodes and returns `{ stop }` (the precedent is `@hafley66/signal-grid`'s `10_render.ts` + `GridView`). A player is `Signal(observable, 0)`, so a player nobody mounted does no work — that property is asserted by a test asserting `frame` stays 0 after a seek with nothing observing it.
- `TestScheduler.run` delegates async/interval/timeout/animation-frame/immediate/timestamp to the virtual clock, so `interval(1000)` written at module scope ticks in virtual ms. It cannot virtualize Promises — that is the silent-loss bug.
- `page.getByTestId(...).click({ position })` gives trusted input (needed for `setPointerCapture`); text-dispatch helpers need the position computed relative to the host, not the strip.
- The repo's per-package gate names are `typecheck` / `test` / `build` / `receipts` / `test:browser`, browser runs go through `scripts/browser-queue.mjs`, screenshots land in `src/__screenshots__/<testfile>/<name>-<browser>-<platform>.png`, and `pnpm release:check` must keep passing.

## Open Questions
1. Initial reveal state: `all` (a diagram in a page is a picture; stepping back to column 0 starts a run) or `0` (explainer by default). Recommendation: `all`.
2. Notes on every revealed marble, or only on the current column. Recommendation: all revealed, dimmed, with the current column's emphasized. A hard length cap either way or the diagram becomes a document with a diagram in it.
3. `lanes.each(outer, ...)` subscribes the outer a second time — harmless for a cold source, wrong for a stateful one. Document it, or make `each` read a lane the registrar already holds.
4. Whether to keep the notation parser at all (user decided: keep, defocus) — do not reopen.
