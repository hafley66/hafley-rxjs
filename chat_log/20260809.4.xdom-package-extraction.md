## Problem/Context
- Task 1 originally added the browser harness TO rxjs-ext. When the user moved
  dom out (task 3), that harness + the browser test + 6 browser devDeps moved
  WITH it to xdom; rxjs-ext was reverted to its pre-task-1 dep set. So the
  browser harness now correctly lives in xdom, not rxjs-ext.
- Task 2's `{b}` ReactNode error and the `@hafley/rxjs-ext` implicit-any error
  were BOTH symptoms of one root cause: rxjs-ext dist not built, so `TAG` was
  `any`, corrupting `derp`'s type downstream. Building dist fixed both at once.
- `createLibConfig` returns a function (defineConfig wraps, returns as-is), so
  grid's `config.build.lib.entry = ...` / `config.test = ...` mutations in its
  vite.config are DEAD CODE (set properties on the function, ignored by Vite).
  grid's `dist/3_react.js` only appears via preserveModules reaching it
  transitively from index.ts. xdom CANNOT rely on that (its core must not
  import the react layer), so xdom uses a STANDALONE vite config with real
  multi-entry + `.tsx` in the dts include.
- vitest 4.1.10: a file matching `include` with no recognized suite = failure.
  rxjs-ext with zero tests exits 1 -> breaks root `pnpm -r test`. Fixed with
  `passWithNoTests` via a `createLibConfig` wrapper (call the inner fn, spread
  test, return).

## Solution/Approach
- **xdom boundary**: moved ALL dom code (events + template + react), not just
  the react layer. xdom owns the concept; rxjs-ext is pure operators. xdom deps
  = `rxjs` (what the code imports) + `react` optional peer. `rxjs-ext`/`signals`
  /`path` NOT added as deps yet — the code doesn't import them; they wire in
  when the deferred builder integrates signal-proxy paths (user confirmed these
  framework packages are fair game for cross-deps when used).
- **Standalone vite config** for xdom: multi-entry `{index, react/index}`,
  dts `include: ["src/**/*.ts","src/**/*.tsx"]`, preserveModules + entryFileNames
  `[name].js`, external from package.json deps/peerDeps. Mirrors createLibConfig
  shape but expresses what the shared helper can't.
- **File renumbering**: `8_domEvents`->`0_domEvents`, `8_domTemplate`->
  `1_domTemplate` (clean numbering for a fresh package). Internal imports +
  screenshot dir renamed to match.
- **devtool-plugin TS7 fixes**: built rxjs-ext dist (2 errors), excluded the
  WIP `0_DebuggerGrid.browser.test.tsx` from tsconfig (4 errors, references
  non-existent module layout), removed 4 dead locals (3 errors), `declare
  global` for `window.____root` (3 errors), `DietOperator<unknown,unknown>[]`
  -> `<any,any>[]` on the pipe impl signature (1 error, RxJS's own escape hatch).

## Key Insights
- `defineConfig(fn)` returns `fn` unchanged (identity for typing). So any
  `config.X = ...` mutation AFTER `const config = createLibConfig(dir)` is a
  no-op. To override: `defineConfig(env => { const c = createLibConfig(dir)(env);
  c.x = ...; return c })` — call the inner fn first.
- One unbuilt dist can cascade into phantom type errors 2 files away (TAG->any
  ->derp->b:unknown->ReactNode). Build before debugging types.
- `boxAttrs` stamps the FULL template skeleton on each Box (`grid/row/expand`),
  not one segment. So nested same-template Boxes compose to a doubled skeleton
  and DON'T match. Single-Box-per-endpoint (full stamp) is the working mode;
  multi-node inheritance = deferred builder. The browser test uses sibling Boxes
  (not nested) to avoid the compose mismatch.
- xdom README quickstart import is `@hafley66/xdom/react` (now the real path).
- `9_scanEager.ts` exists in rxjs-ext but was NEVER exported in index.ts
  (pre-existing, left alone).
