# Session: dom-route-spec-signal-event-bus

## Goal
Unify grid state + events + DOM interaction under one dialect: signals as the
bidirectional primitive, `mergeByKey` as the event-bus fold, `Dom` as the
universal interactive-element authoring helper, and the DOM nesting of `Dom`
templates flattened into an OpenAPI-style component spec (routes LHS + types
divorced + payloads RHS).

## Problem/Context
- `createLazyTree` minted its own `expanded: Signal<ReadonlySet<string>>` AND its
  own `rows`, duplicating the `expanded` slice already in `GridState`
  (`packages/grid/src/1_types.ts:34`) and the `rows` signal on the grid. That is
  "new fields as we go" — state must live in one injected bag.
- `createGrid` already accepts `config.state?: Signal<GridState>`
  (`packages/grid/src/1_types.ts:54`, used at `2_createGrid.ts:49`). The injection
  seam exists; the lazy tree ignored it.
- A separate `expand$` event observable was bolted on via
  `onExpand.$ as unknown as Observable<string>` — the `as unknown` cast was the
  smell of a wrong abstraction. The signal primitive is already bidirectional
  (`.$()` get latest tick, `.subscribe()` the stream); a parallel event signal
  doubles the primitive for no reason.
- Event signals are NOT yet lazy in memos: `.$()` get unconditionally calls
  `dependencyCollectors.at(-1)?.(proxy)` (`1_SignalCreator.ts:169`), so reading
  an event signal inside a computed memo registers it as a dep and emit
  invalidates the memo.

## Solution/Approach
The unified dialect, assembled from existing primitives:

1. **One state bag, injected.** `createDefaultGridState({...overrides})` -> 
   `createGrid({ state })`. All grid state (including `expanded`) is a slice of
   this one signal. Rename `defaultGridState` -> `createDefaultGridState`, add
   `overrides: Partial<GridState>` merge.
2. **Event bus = keyed-object signal.** `Signal<GridEvents>()` where
   `GridEvents = { expandClick: {rowId}, expandCloseAll: {}, sortChange: {...} }`.
   Scope/pre-narrow by deep-proxy dot path: `events.expandClick` (proxy nested
   access, already implemented `1_SignalCreator.ts:266-282`). No discriminated
   union, no `ev.type === ...` narrowing.
3. **Fold primitive = `mergeByKey` / `mergeByKeyScan`** (already in
   `packages/rxjs-ext/src/3_mergeBy.ts:15,81`). `mergeByKey` emits `{key,value}`
   per event; `mergeByKeyScan` folds into latest-per-key state object. The
   accumulator-inside-the-graph the session kept reaching for.
4. **`Signal(observable)` is dual.** Observable source merged with imperative
   `.$()` writes (`1_SignalCreator.ts:72-81`), refCount-managed. FRP source +
   imperative escape hatch in one node. Terminate chains here, NEVER naked
   `.subscribe()` — subscription rides refCount-on-read or a component hook.
5. **`produce` is the commit body.** In the scan fold, immer `produce` is the
   transactional draft mutation applied when the (debounced) channel drains. One
   `produce` folds a tick's batch, not one per event. The whole fold is morally a
   debounced-channel saga: collect (render pass / event put) -> channel
   (mergeByKey) -> debounce (tick coalesce) -> drain (scan) -> commit (produce).
6. **Expansion is one built-in mechanism, two flavors.** Row-tree (`getSubRows`)
   and master-detail (`renderSubComponent`) share `expanded` state + the expand
   column. Loading is an expansion property (not a tree property), derived per id:
   `expanded[id] && contentNotPresent(id)`. Tree content = children in rows;
   detail content = detail data resolved.
7. **`Dom(template)` already exists** (`packages/rxjs-ext/src/8_domTemplate.ts:82`)
   as the routed DOM-event selector. `fromIdPathRoute` was a duplicate I almost
   rebuilt. Real API: `Dom(t).id(values)` / `.with(values)` / `.$eventName`
   (delegated event observable carrying `{delegateElement, params}`). DOM events
   treated as a routed API: a click on an expand cell = `GET /row/:rowId/:colId/expand`.
8. **DOM nesting = route tree -> component spec.** Author interactive elements as
   nested `Dom` templates. Parent path + child relative path compose via
   `IPath.concatenate` (`path/src/1_path.ts:253`). Flatten the tree into a spec:
   routes (LHS, from nesting), param types (divorced, `ValuesOf<Path>` type-level
   only `1_path.ts:278`), payloads (RHS, zod schema via `route(t,q,payload)`
   `2_route.ts:82`). Output = the component's OpenAPI spec, auto-derived from
   how the `Dom`s were nested.

## Key Insights
- **Signals are bidirectional.** `.$()` is latest tick (get), `.subscribe()` is
  the stream. A linear state crossing a boundary is ONE signal. Do not mint a
  parallel event observable. `Signal(observable)` further merges an observable
  source with imperative `.$()` writes (`1_SignalCreator.ts:72-81`) — dual node.
- **`mergeByKey` / `mergeByKeyScan` are the fold primitive** the session kept
  reaching for. They exist (`rxjs-ext/src/3_mergeBy.ts:15,81`). `mergeByKey` =
  event bus (`{key,value}` per emit); `mergeByKeyScan` = latest-per-key state.
- **Subscription graph mastery = never calling `.subscribe`.** Terminate in
  `Signal(obs)`; refCount subscribes on read, tears down on last reader
  (`1_SignalCreator.ts:80`). `.subscribe` and `pipe(scan)` outside a `Signal()`
  both bypass the graph.
- **`produce` is the commit body** of a debounced-channel saga. One `produce`
  per drained tick batch, not one per event.
- **Expansion is built-in and shared.** Row-tree + master-detail share
  `expanded` + the expand column. Loading derives per expanded id; it is an
  expansion concern, not a tree concern. There is no such thing as a "lazy tree"
  abstraction — signals are already lazy (computed memo re-evaluates on read,
  refCount tears down with no readers).
- **`Dom(template)` already exists** and treats DOM events as a routed API.
  `fromIdPathRoute` was a reinvention of it.
- **DOM nesting = route nesting.** `IPath.concatenate` composes parent+child;
  `routeMap` + `ValuesOf` + `toOpenApiPattern` flatten a nested `Dom` tree into a
  spec. Types (`ValuesOf<Path>`) are divorced from routes (pure type-level,
  independent of runtime route strings). `route(t, query, payload)` already
  separates path-types (`RoutePathOutput`) from payload schema.
- **Event signals currently track in memos** (`1_SignalCreator.ts:169` no guard).
  Fix is one line: gate the collector on the `event` flag.
- **`:param` colon syntax is native** to both `Dom`'s regex AND `@hafley66/path`
  (`1_path.ts:72` accepts `{name}` and `:name`). `{number:name}` gives typed scalars.
