## Problem/Context
- Large D2 documents produce large SVG DOM trees and Instant currently chokes on the epic render.
- The desired debugger must make live app behavior visible on screen: DOM node count for the active tab/probe root, committed component render counts, recent structured probe events, and later parse/render/projection/trace timings.
- The debugger display must not count itself or create MutationObserver/render feedback loops.
- D2 and Mermaid sources are captured across file/Git/message revisions. Stable source entity IDs drive diffs. SVG supplies render geometry. Human placement remains separate from source topology.
- Markdown links should resolve through exact URI/heading/symbol matches, approximate text candidates, and LSP definition/reference/document-link evidence.
- Sprefa dataflow output can become D2, allowing the same D2 analysis, rendering, geometry, diff, and projection mechanics.
- Large sequence diagrams need compact and folded modes. Trace events should animate a marble along stable message/edge identities.
- AI-authored D2 will later follow named class conventions for entities, sections, sequence actors/messages, trace ports, expandable text, and source links.
- The Markdown parser and fact emitter should become standalone Rust library/CLI boundaries that shell pipelines, DL6 programs, and Sprefa can all consume.

## Solution/Approach
- Keep the durable model, parser output, geometry, diffs, event journal, and projection inputs framework-free.
- Permit React adapters for the first Instant/Cytoscape/XYFlow integration.
- Use immutable artifact revisions and entity graphs, content-addressed render caches, separate placement journals, and keyed entity diffs.
- Use `@hafley66/grid` for all network/session/trace row views. Graph, waterfall, sequence, and marble projections consume the same selected row set and entity IDs.
- Extract Instant Markdown parsing, sections, source spans, links, embedded diagrams, and document state into grapht. Instant retains filesystem access, Dockview registration, native open/reveal, host preferences, and application styling.
- Record library dependencies and capability surfaces for network/graph geometry without qualitative build-versus-buy statements.

- Identity, topology, render geometry, and user placement require separate planes and write paths.
