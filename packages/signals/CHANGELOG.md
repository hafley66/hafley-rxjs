# @hafley66/signals

## Unreleased

### Minor Changes

- Pattern dispatch over the signal tree (`src/12_match.ts`):
  - `source.switch$(handlers)` — flat, exhaustive dispatch over a record of event ports. A state
    source replays each key's current value on subscribe; an event source fires on the next write
    only.
  - `source.match$(handlers)` — dotted-path dispatch including `{hole}` patterns. Exact patterns
    subscribe their node directly; holed patterns subscribe the meta stream and match concrete
    write paths at dispatch time, so indexes that do not exist yet match as soon as they are
    written. Handlers receive the live child node plus the extracted holes, and handler errors are
    contained per emission.
  - Both attach through a `special$` postfix-method registry in `src/1_SignalCreator.ts`, keeping
    the core free of any one plugin's knowledge.

### Minor Changes (types)

- Dotted-path type layer in `src/0_types.ts` backing `match$`: `SignalPath`, `SignalPathValue`,
  `PatternValue<E, K>` (what a handler's `it` node reads and writes), and `ArgsOf<P>` (hole values
  parsed by `@hafley66/path`). Exported from the barrel.
- `pipe$` overloads restated under the uniform formatter; no signature change.

### Fixed

- `match$` holed patterns attached at a nested node are rebased to the node's path: the pattern
  matches writes under that node instead of being compared against root-global write paths at the
  wrong depth, where it could never fire.
- `match$` and `switch$` reject a non-object handlers argument with a `TypeError` instead of
  silently enumerating it (a string became per-character exact patterns whose handlers threw
  inside the per-emission error containment).
